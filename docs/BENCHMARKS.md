# Benchmarks

This page is generated by `node scripts/benchmark.mjs` from `artifacts/benchmark-results.jsonl` once a team runs the
harness. No results are committed: results depend on the model each team brings and on the machine it runs on, so
the harness is the deliverable, not a table. For a narrated end-to-end run with its counts, see
[reference-run.md](reference-run.md).

## What is measured

Two demo apps with switchable seeded defects and answer keys ([ground-truth/](../ground-truth/)). Every configuration
runs twice from a freshly reset app:

- **Every seeded defect on**: which defects it finds, and which it **confirms** (the finding reproduced on both
  model-free replays). A defect is credited only to a check that is about it: a rule must check that defect's fields
  on the response that shows it; a cross-endpoint defect is credited only to a prediction.
- **Every seeded defect off**: any proven finding is a **false positive**, reported by source (oracle, AI-written
  rule, twin prediction). Suspicions from the model are listed but never fail a build.

Configurations are named by strategy: no AI (sweep, probes, oracles), no AI with every role and the project's twin
predictions (survey), Guided and Hybrid with the model you pass. Each row also records model calls and minutes.

## Run it

```bash
node scripts/benchmark.mjs                                     # no-AI rows on the demo shop
node scripts/benchmark.mjs --app hotel                         # the same on Demo Hotel
node scripts/benchmark.mjs --app hotel --model provider:model  # plus the AI rows, with your model
node scripts/twin-score.mjs --app hotel                        # app twin, understanding and journey accuracy vs the answer key
node scripts/benchmark.mjs --report                            # rewrite this page from saved results
```

## Method notes

- Same mission, stories, secrets and setup hook in every run of an app; probes and replay confirmation on; repro
  shrinking off.
- Rule findings no seeded defect explains are false positives even when the engine labelled the rule as probably
  wrong; the label is shown in brackets.
- Each app also has one real bug nobody seeded: the shop returns HTTP 500 for a fractional quantity, and the hotel
  accepts an email such as `john.doe@.com`. When found, they count as unexplained (a strict reading).
- Threats to validity and the head-to-head method for comparing tools are in [evaluation.md](evaluation.md).
